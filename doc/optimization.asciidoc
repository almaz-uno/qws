= QWS performance optimization
:toc:
:toclevels: 3

== Introduction

This document contains recommendations for optimizing the performance of QWS, especially in the carousel and grid modes. The main problems: slow drawing with a large number of windows and high CPU and memory consumption.

**Profiling status:** ✅ Profiling is fully implemented and actively used. The collected profiles are in the `profiles/` directory.

== Current state of the architecture

=== Technologies in use

* **X11 library:** `github.com/jezek/xgb` (X Go Binding)
* **Composite extension:** Used to capture windows in `pkg/composite/capture.go`
* **XSHM:** Already implemented and available (`c.shmAvailable`)
* **Rendering:** Two backends — CPU (`renderer-cpu.go`) and OpenGL (`renderer-opengl.go`)
* **Drawing:** Through `xproto.PutImage`, split into strips to get around the limits of X11

=== Critical parts of the code

. **`pkg/composite/capture.go`** — thumbnail capture
.. Strategies: XComposite+XSHM → XComposite+XGetImage → Direct+XSHM → Direct+XGetImage
.. Scaling through `golang.org/x/image/draw`
.. Problem: results are not cached between shows

. **`pkg/carousel/renderer-cpu.go`** — CPU rendering
.. `Draw3DCarouselWithData()` — draws the carousel
.. `DrawGridLayout()` — draws the grid
.. Uses `github.com/fogleman/gg` for vector graphics
.. Problem: many allocations on every draw

. **`pkg/carousel/window.go`** — output to the screen
.. `DrawImage()` splits the image into strips
.. Uses `xproto.PutImage` → `xproto.CopyArea`
.. Problem: does not use XSHM for output

. **`pkg/ui/selector.go`** — the main controller
.. `prepareThumbnails()` — preparation without a cache
.. `render()` — called on every change
.. Problem: X11 commands are not batched

=== 1. Thumbnail caching (CRITICAL)

==== Problem
`prepareThumbnails()` creates a new array every time, although the thumbnails are already in `win.Preview`. However, scaled versions are not cached between shows of the selector.

==== Solution
Add a cache of scaled thumbnails with LRU eviction:

[source,go]
----
// In pkg/ui/selector.go
type thumbnailCache struct {
    items    map[xproto.Window]*cachedThumb
    maxSize  int
    mu       sync.RWMutex
}

type cachedThumb struct {
    image    image.Image
    lastUsed time.Time
}

func (tc *thumbnailCache) Get(window xproto.Window) (image.Image, bool) {
    tc.mu.RLock()
    defer tc.mu.RUnlock()
    if thumb, ok := tc.items[window]; ok {
        thumb.lastUsed = time.Now()
        return thumb.image, true
    }
    return nil, false
}

func (tc *thumbnailCache) Put(window xproto.Window, img image.Image) {
    tc.mu.Lock()
    defer tc.mu.Unlock()
    tc.items[window] = &cachedThumb{
        image:    img,
        lastUsed: time.Now(),
    }
    tc.evictOldest()
}
----

**Priority:** HIGH +
**Expected effect:** 50-70% less thumbnail preparation time

=== 2. Object Pool for images

==== Problem
Every call of `Draw3DCarouselWithData()` creates a new `*image.RGBA` and temporary structures through `gg.NewContext()`.

==== Solution
Use `sync.Pool` to reuse buffers:

[source,go]
----
// In pkg/carousel/renderer-cpu.go
var imagePool = sync.Pool{
    New: func() interface{} {
        return image.NewRGBA(image.Rect(0, 0, 1920, 1080))
    },
}

func Draw3DCarouselWithData(...) *image.RGBA {
    img := imagePool.Get().(*image.RGBA)
    defer imagePool.Put(img)

    // Check the size
    if img.Bounds().Dx() < cfg.Width || img.Bounds().Dy() < cfg.Height {
        img = image.NewRGBA(image.Rect(0, 0, cfg.Width, cfg.Height))
    }

    // Use the existing buffer
    dc := gg.NewContextForRGBA(img)

    // ... rest of rendering

    // Do NOT return img from the pool, clone it before return
    result := image.NewRGBA(img.Bounds())
    copy(result.Pix, img.Pix)
    return result
}
----

**Priority:** MEDIUM +
**Expected effect:** 20-30% fewer memory allocations

=== 3. XSHM for image output

==== Problem
`window.DrawImage()` uses `xproto.PutImage`, which copies the data through the socket. Even though the Capturer has XSHM, output goes through PutImage.

==== Solution
Implement an XSHM pixmap for output:

[source,go]
----
// In pkg/carousel/window.go
type Window struct {
    // ... existing fields
    shmPixmap   xproto.Pixmap
    shmSegment  shm.Seg
    shmData     []byte
    shmAvailable bool
}

func (w *Window) initSHM() error {
    if err := shm.Init(w.conn); err != nil {
        return err
    }

    // Create a shared memory segment
    size := int(w.width) * int(w.height) * 4
    shmid, addr, err := createSHM(size)
    if err != nil {
        return err
    }

    w.shmSegment, _ = shm.NewSegId(w.conn)
    shm.Attach(w.conn, w.shmSegment, uint32(shmid), false)

    w.shmData = (*[1 << 30]byte)(unsafe.Pointer(addr))[:size:size]
    w.shmPixmap, _ = xproto.NewPixmapId(w.conn)

    // Create pixmap using shared memory
    shm.CreatePixmap(w.conn, w.shmPixmap, xproto.Drawable(w.window),
        w.width, w.height, w.depth, w.shmSegment, 0)

    w.shmAvailable = true
    return nil
}

func (w *Window) DrawImage(img image.Image) error {
    if w.shmAvailable {
        return w.drawImageSHM(img)
    }
    return w.drawImagePutImage(img)
}

func (w *Window) drawImageSHM(img image.Image) error {
    // Copy straight into shared memory
    bounds := img.Bounds()
    i := 0
    for y := bounds.Min.Y; y < bounds.Max.Y; y++ {
        for x := bounds.Min.X; x < bounds.Max.X; x++ {
            c := color.RGBAModel.Convert(img.At(x, y)).(color.RGBA)
            w.shmData[i] = c.B
            w.shmData[i+1] = c.G
            w.shmData[i+2] = c.R
            w.shmData[i+3] = c.A
            i += 4
        }
    }

    // Just copy the pixmap — the data is already in shared memory!
    xproto.CopyArea(w.conn, xproto.Drawable(w.shmPixmap),
        xproto.Drawable(w.window), w.gc, 0, 0, 0, 0, w.width, w.height)

    return nil
}
----

**Priority:** HIGH +
**Expected effect:** 40-60% less time drawing to the screen

=== 4. Batching X11 commands

==== Problem
`window.DrawImage()` calls `Sync()` after every draw, which costs a round trip.

==== Solution
Remove the unnecessary `Sync()` calls and use `Flush()`:

[source,go]
----
// In pkg/ui/selector.go
func (s *Selector) render(thumbnails []image.Image) {
    windowData := s.prepareWindowData()

    var img *image.RGBA
    if s.config.LayoutMode == "grid" {
        img = s.renderer.DrawGridLayout(windowData, s.selectedIndex, s.hoverIndex, s.config)
    } else {
        img = s.renderer.Draw3DCarouselWithData(windowData, s.selectedIndex, s.hoverIndex, s.animOffset, s.config)
    }

    s.window.DrawImage(img)

    // One Flush at the end of all operations
    s.window.conn.Flush()
}

// In pkg/carousel/window.go
func (w *Window) DrawImage(img image.Image) error {
    // ... rendering code ...

    // REMOVE: w.conn.Sync()
    // Let the caller Flush when needed
    return nil
}
----

**Priority:** MEDIUM +
**Expected effect:** 10-20% lower latency

=== 5. Scaling optimization in composite/capture.go

==== Problem
Scaling is done on every capture. `focus.Watcher` already has a thumbnail cache, but it remains to be confirmed that it is used optimally.

==== Solution
Check that the cache does not overflow and that thumbnails are reused:

[source,go]
----
// In pkg/focus/watcher.go - there is a cache already!
// Check that captureThumbnail is called only when needed

func (fw *Watcher) GetThumbnailOrCapture(window xproto.Window) (image.Image, bool) {
    // Check the cache first
    if thumb, ok := fw.GetThumbnail(window); ok {
        return thumb, true
    }

    // Capture only if it is not there
    fw.captureThumbnail(window)
    return fw.GetThumbnail(window)
}
----

=== 7. Grid rendering optimization

==== Problem
`DrawGridLayout()` draws ALL windows, even those outside the screen (although this is rare for the grid).

==== Solution
Add culling for large lists:

[source,go]
----
// In pkg/carousel/renderer-cpu.go
func DrawGridLayout(windowData []WindowData, selected int, hoverIndex int, cfg Config) *image.RGBA {
    // ... existing setup ...

    // Compute the viewport
    viewportBounds := image.Rect(0, 0, cfg.Width, cfg.Height)

    for i, win := range windowData {
        row := i / cols
        col := i % cols

        x := offsetX + spacing + float64(col)*(tileW+spacing)
        y := offsetY + spacing + float64(row)*(tileH+spacing)

        // Culling: skip the tiles outside the visible area
        tileBounds := image.Rect(
            int(x), int(y),
            int(x+tileW), int(y+tileH),
        )
        if !tileBounds.Overlaps(viewportBounds) {
            continue // do NOT draw
        }

        drawGridTile(dc, &win, x, y, tileW, tileH, i == selected, i == hoverIndex, cfg)
    }

    return getImageRGBA(dc)
}
----

**Priority:** LOW (relevant only for >50 windows) +
**Expected effect:** 30-50% faster with a large number of windows

=== Performance monitoring in production

=== Potential problems

. **XSHM may be unavailable** over SSH X11 forwarding
.. Solution: fall back to PutImage (already implemented in capture.go)
.. Detect a remote connection and disable XSHM automatically

. **Object Pool may not help** if the images differ in size
.. Solution: several pools for common sizes (1920x1080, 1280x720)

. **The cache may take a lot of memory** with a large number of windows
.. Solution: LRU with a configurable limit (for example, 50 thumbnails max)
.. A configuration option: `cache_size: 50`

=== Alternative approaches (for the future)

. **XRender for compositing** — may be faster for blend operations
.. Requires a study of the XRender extension in xgb
.. Potentially more efficient than CPU rendering

. **Pre-rendering grid tiles** — if the layout does not change often
.. Cache whole rendered tiles
.. Relevant if the tiles are static

. **Asynchronous thumbnail capture** — do not block the UI
.. Show a placeholder while the capture is in progress
.. Update the UI when the thumbnail is ready
