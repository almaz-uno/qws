== The animation off now

`appearance.animation.enabled: false` reaches `parseAnimation`
(`pkg/ui/effects.go`), which leaves every duration 0: a step at once, no
fade, no hover animation, no convergence of 028. The animator — the
presenter that composes — stays: the layers are drawn, a switch of the
layout is shown from them (028, D7). The key is a bool, its flag
`--appearance-animation-enabled` a bool flag, default `true`. None of the
configuration files of ws1, ws2 and ws3 sets it.

== A VNC viewer

A connected viewer is a TCP connection in the state ESTABLISHED on the
local port the VNC server listens on: in `/proc/net/tcp` and
`/proc/net/tcp6` a line of local port `170C` (5900) and state `01`. On ws2
on 2026-10-07: `[::1]:5900 ← [::1]:47302`, `X0tigervnc`, the viewer through
an ssh tunnel. ws2 also runs `Xvnc :1 -rfbport 15900`, a display of its
own, which qws's service on `:0` does not serve.

== The look for a viewer

`BenchmarkViewerConnected` (`pkg/ui/viewer_test.go`) reads the two tables
as the switcher does, for a port no connection is on: on ws1 — 24 CPUs,
249 lines in `/proc/net/tcp` and 37 in `/proc/net/tcp6` —, 5.3 ms a look,
1000 looks, 2026-10-07. Benchmarks of the same reads, not kept: a table
read whole in one call of 1 MB takes as long as through a `bufio.Scanner`,
and the tables apart 2.8 ms the first, 2.4 ms the second, for seven times
fewer lines. The time is the kernel's: for each table it walks
its hash of connections, of a size by the memory of the machine, not by
the connections in it. Not the 0.1 ms that D4 first said: a look made
before the first frame would delay it by as much, so it is made while the
frame is drawn — 27–52 ms on ws2 in the batches of the research — and
waited for before it is presented.

== The batches as test data

`pkg/ui/testdata/vnc-a.txt` and `vnc-b.txt` hold of the two logs what the
count needs and nothing else: of each record "Animation frame" with an
interval, its activation, its kind and its interval in microseconds — a
line a run of records of one kind in one activation, in their order —, and
the period in a comment. No intervals lie within 2 µs of 1.25 periods,
7583.35 µs: the rounding to the microsecond changes no frame's lateness.
Made on ws1 from the logs of the research, the colours of the console
writer stripped:

[source,sh]
----
for b in A B; do
  l=$(echo $b | tr AB ab)
  {
    printf '# The frames of batch %s of specs/031-animation-auto, research: ws2, 165 Hz,\n' $b
    printf '# the records "Animation frame" with an interval, in their order. A line\n'
    printf '# is a run of records of one kind in one activation: the activation, the\n'
    printf '# kind, the intervals in microseconds.\n'
    printf '# period_us 6066.679\n'
    sed 's/\x1b\[[0-9;]*m//g' ~/.cache/qws-diag/vnc-$b.txt |
    awk '/Animation frame/ {
      a = k = i = ""
      for (n = 1; n <= NF; n++) {
        split($n, f, "=")
        if (f[1] == "activation") a = f[2]
        else if (f[1] == "kind") k = f[2]
        else if (f[1] == "interval_ms") i = f[2]
      }
      if (i == "") next
      us = sprintf("%.0f", i * 1000)
      if (a == pa && k == pk) { line = line " " us; next }
      if (line != "") print line
      line = a " " k " " us; pa = a; pk = k
    }
    END { if (line != "") print line }'
  } > pkg/ui/testdata/vnc-$l.txt
done
----
