== What and why

Since 1.1.0 every qws instance captures the visible windows through the GPU
when their contents change (specification 008), and pauses those captures
while its own switcher is shown (007). It does not pause for the switcher of
another instance. While one shows its switcher, another captures the windows
that change meanwhile, a terminal that prints, an editor, and takes the GPU
and the X server from the frames: on E1, beside the two services the author
ran then, the step of the carousel missed 1.10 % of its frames instead of
0.51 %, the fade-in 9.8 % instead of 0.45 % (specification 010, research,
"The control"). The author asked (2026-10-01) that the snapshots pause while
any switcher is shown.

The same evening the author removed the second service,
`qws-workspace.service`; one instance remains. A second one still comes and
goes — a trial build, a measurement, the second service back — and the
pause is for it. For the one instance alone the change brings the fix found
on the way: while its own switcher is shown, its snapshotter spun on a CPU
for every window that came due.

The specification is a delta to `develop` at `f90abc7` (1.2.0). Unchanged:
what is captured and when, but for the pause; the capture at an activation,
`Refresh`; the pause for the instance's own switcher; the snapshots on the
CPU of the focus watcher, without GLX; the configuration.

== Decisions

Author, 2026-10-01: snapshots pause while the switcher of any qws instance
is shown. The author removed `qws-workspace.service` at 21:49 the same day,
on purpose.

Made on the way, 2026-10-01, for the author to confirm:

* the instances find each other's switchers through a property of the root
  window listing the overlay windows, and follow the map state of those
  windows by their structure events — not a property set while a switcher
  is shown, which an instance killed while showing would leave set and
  pause the others for good: the X server destroys the windows of a client
  that dies, and the others see it;
* an overlay is listed when it is created, not at each activation: the list
  changes a few times a day, the activation does not wait for it;
* the snapshots on the CPU of the focus watcher keep pausing for their own
  switcher only: they run without GLX, on none of the author's machines;
* the loop of the snapshotter waits while paused, found on the way: since
  1.1.0 a window that comes due while its switcher is shown arms
  the loop's timer in the past, and the loop wakes at once, skips the
  capture for the pause and arms it again — it spins on a CPU for as long
  as the switcher is shown (`pkg/snapshot`, `run` and `nextDue`); paused for
  every switcher, the other instance would spin as well;
* a fix, without a key: a patch — 1.3.2, as 1.2.1, 1.3.0 and 1.3.1 went out
  meanwhile.

== Behavior

. *The list.* The root window has the property `_QWS_SWITCHERS`, of the type
  `WINDOW`, format 32: the overlay windows of the qws instances of the
  display. An instance lists its overlay when it creates it — at its first
  activation, and again when the monitor changes. It grabs the server,
  reads the list, drops the windows that no longer exist, appends its own
  and writes the list back, so that two instances listing at once lose
  neither.
. *The pause.* The snapshotter of every instance follows the windows of the
  list — read when it starts and whenever the property changes — by their
  structure events: mapped, unmapped, destroyed. While any of them is
  mapped it takes no snapshot on change, as while its own switcher is
  shown; the snapshots that come due meanwhile are taken when the last of
  them is unmapped. The snapshots of an activation, before its first frame,
  are taken as before.
. *Waiting.* While paused, the loop of the snapshotter arms no timer for
  the windows that come due: it wakes for its events, for the snapshots of
  an activation and when the pause ends, and only then for a window due.
. *An instance that dies* leaves its window in the list; the X server
  destroys the window, the snapshotters see it destroyed and stop
  following it, and the next instance to list its overlay drops it.
. *Older versions* neither list their overlay nor follow the list: beside
  them, an instance of this change behaves as 1.2.0 does.

== Metrics

As in 010. The snapshots of an instance are its records `Snapshot`, at debug
level, with their cause — `change` or `activation` — and their time; the
switcher of another instance is shown from the first frame of an activation
to the unmapping of its overlay, from its records `Frame` and `Window
activated` and the end of its fade-out.

Session S4:: S2 of 007 on E1, with the two services stopped and two
instances of this change in their place — the flags of the services, debug
logging in JSON — so that their snapshots can be read.
