The plan of the options recommended in the specification; should the author
choose others, it is written again.

== Approach

*Naming.* `captureGPU` of a stale window asks `namePixmap`: the window's own
pixmap, as now; on a refusal, the window's attributes — not viewable, then
`errNotViewable` as now; viewable, the parents up to the root, `QueryTree`,
the first whose pixmap `NameWindowPixmap` names. The window keeps the
ancestor (`via`) and the ancestor's visual (`pixVisual`), and `captureGPU`
returns `errNotBound` without binding: `capture` takes it by RENDER, as a
window the GPU refused. No ancestor: `errNotRedirected`, and `capture` takes
the window on the CPU, through `composite.Capturer`, whose direct
`GetImage` of the window includes its children.

*RENDER from a rectangle.* `xrender.thumbnail` takes the rectangle of the
window in the pixmap. Where it does not start at the pixmap's corner, it is
copied first, `CopyArea`, into a pixmap of the window's size and depth: the
passes of 018 then pad at the window's own edges, not with the frame's
decoration around it. The offset is asked at each capture,
`TranslateCoordinates` of the window to the ancestor, plus the ancestor's
border.

*Named anew.* A map or an unmap of the window or of its frame makes it
stale, as now; and a ConfigureNotify of the frame the window is taken from,
since a frame of a new size has a new pixmap.
