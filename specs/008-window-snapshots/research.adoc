== Which windows have contents

i3 unmaps the windows of hidden workspaces and of hidden tabs; an unmapped
window has no pixmap in the X server. Of the 30 client windows of ws1 at the
time, one was viewable. Only viewable windows can be captured; the others
keep what was taken while they were viewable.

== Scaling in the X server

RENDER scales the named pixmap in the server: halved by bilinear filtering,
a 2×2 box at that scale, while more than twice the thumbnail, then one
bilinear pass, `RepeatPad` at the edges; the thumbnail alone comes over a
segment made once. 0.55–0.93 ms at the median. Against the area average of
the same capture computed on the CPU, mean absolute difference per channel
1.16, worst 58 — `x/image/draw` BiLinear 1.05 and 42, CatmullRom 0.96 and
41. RENDER 0.11 on ws1, filters nearest, bilinear, convolution, fast, good,
best.

== Scaling on the GPU in qws

`GLX_EXT_texture_from_pixmap` binds the named pixmap as a texture in a GL
4.6 core context on a pbuffer of 1×1; a fragment shader averages the source
rectangle of each pixel of the thumbnail, weighting each texel by its
overlap; `glReadPixels` reads the thumbnail. `GLX_Y_INVERTED_EXT` of the
FBConfig says which way the rows go: 1 on ws1, read in the shader.

[cols="3,1",options="header"]
|===
| Variant | ms, median of 9
| pixmaps named and bound for each snapshot | 3.86
| pixmaps kept; the texture released and bound again for each | 0.58
|===

Against the area average computed on the CPU from a capture right after:
mean absolute difference 0.00, worst 1 — rounding.

`GLX_EXT_texture_from_pixmap` is offered on ws1 and ws2 (NVIDIA 580) and on
ws3, whose X server runs on the Intel GPU through Mesa 22.3.6, GL 4.6 core.
ws1 also has DAMAGE, Composite, RENDER, MIT-SHM, XFIXES and Present.

== Found on the way

* A texture bound to a pixmap has no mipmaps; with the default minifying
  filter, which uses them, it is incomplete, and `texelFetch` reads black.
  The texture of a window gets `NEAREST`.
* The X server takes requests of at most 256 KB without BIG-REQUESTS; the
  test of K4 uploads its images in strips.
* The default X error handler of Xlib ends the process. A window can be
  destroyed between its event and its capture, so the display of the
  snapshots counts its errors and returns them; other displays keep the
  handler they had.
* DAMAGE reports the first change after each subtraction. The subtraction
  comes before a capture, viewable or not: a hidden window left damaged
  would never report again.
* i3 hides a window by unmapping its frame, the window's parent; the
  window itself stays mapped, unviewable. The snapshotter follows the
  structure of the frame as well: when it is mapped again, Composite has
  given the window a new pixmap, and the old one is named no more.
