== Approach

*The context.* `glx.Context.NewShared` creates, on an Xlib display of its
own, a pbuffer of 1×1 and a direct GLX 4.6 core context whose share context
is the presenter's, and makes it current on the calling thread, locked to
it — as `NewOffscreen` of 008 does for the snapshots, with a handler of X
errors of the same design: installed once, counting the errors of its
display, passing those of the others on.

*The uploader* is a goroutine on that thread, started by the presenter when
it creates its GL objects. It runs jobs — closures of GL commands, given its
own pixel buffer — in the order queued, each followed by a fence and a
flush, and hands the fence back. The presenter keeps, for each job whose end
it has not taken, a handle: whether the uploader has issued it, whether its
fence has signalled (`glClientWaitSync`, timeout 0), and a wait — the CPU for
the issue, the GPU, by `glWaitSync`, for the rest.

*The presenter*:

* `SetLayer` generates the texture name, as before, and queues the
  definition of the texture, through the uploader's pixel buffer; a layer
  set anew waits first for a fence of the frames so far. A frame that draws
  the layer — the base or an item of a scene — takes the job's end before:
  signalled, or the GPU waits.
* `StageFrame` queues one job a call: for a new staging, a wait for a fence
  of the frames so far and the copy of the texture of the last frame, then
  the pieces of the call, 64 rows each through the pixel buffer. The last job
  is kept; a later one ends after it, so the earlier fence is only deleted,
  its error kept. `PresentStaged` takes the last job's end before it swaps
  the textures; `draw`, which writes the texture of the last frame, takes it
  first while a copy is among the jobs.
* `Bind` for a window of another size, `DropLayers` and `Close` wait for the
  jobs queued to complete before they reallocate or delete textures.
* `UploadWaits` counts the jobs a frame waited for, by the frame presented
  last.

Without a shared context, every path is that of 1.2.0, in the presenter's
context.

== What is kept

The loop of `pkg/ui/animation.go` — `waitFrame`, `frame`, `uploadIdle`,
`pauseUpload`, `spinAhead` — and the scenes it composes. The frame at rest
reaches the window through the same texture, copy and rows as in 1.2.0, so
its bytes are those of `cpu`; K1 checks it for both kinds of uploads.
