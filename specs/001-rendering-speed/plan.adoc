== Approach

Drawing and presentation are separated. Drawing is always the `cpu` code in
`pkg/carousel/renderer-cpu.go`; the `renderer` key chooses only how the
overlay window presents a finished `*image.RGBA`:

* `cpu` — `Window.DrawImage` as today: BGRA conversion, `PutImage` strips,
  `CopyArea`, `Sync`;
* `glx` — the overlay window is a GLX drawable; the frame is uploaded with
  `TexSubImage2D` into a texture of the window size, drawn as one full-window
  quad with `GL_NEAREST`, blending and `GL_DITHER` disabled, then
  `glXSwapBuffers`.

Bit-exactness of `glx` follows from the construction and is checked by K2
and K3; bit-exactness of `cpu` against `develop` is checked by K1 after every
change to the shared drawing code.

== Measurement

Timings are logged at debug level (`-v`) as zerolog fields in milliseconds,
one record per frame with the metric, the phase durations, the renderer and
the activation number; `measure.sh` runs the instance with `log.format: json`.
P for `glx` needs `glFinish()`, which is called only while timings are
logged: without it the swap returns earlier, so the production path is not
slower than the measured one.

The digests of Σ depend on font files: the scenes use fonts from
`golang.org/x/image/font/gofont` written to temporary files, except the
placeholder, which hard-codes DejaVu Sans (`renderer-cpu.go:575`). The test
records the SHA-256 of each font file next to the frame digests and skips —
rather than fails — a scene whose font file on the host differs.

== Stages

Each stage leaves the program working and ends with K1, K9 and a run of S1
recorded in `research.adoc`.

. *Harness on `develop` code.* The timings, the frame counter, `measure.sh`;
  baseline: three runs of S1 for `cpu`, one run for today's `glx`, for
  reference only; then Σ and the digests of K1. No behaviour changes.
. *GLX presenter.* `pkg/glx`, the window visual, the rebinding, the
  presenter, removal of the GPU scene and of GLFW, the fallback, the frame
  dump. K2–K4, then S1 for both renderers.
. *Bit-exact savings in the shared drawing code,* one at a time, in the order
  the profile of stage 2 suggests. Candidates: reusing the canvas between
  frames; drawing placeholders once per activation; a cache of transformed
  thumbnails by source image and transform. A candidate stays only if S1
  shows a gain in M2 or M3 beyond the spread of the baseline runs; the result
  of each is recorded in `research.adoc` either way.
. *Results.* K1–K9 against the targets, the "Results" section and `:status:`
  of the specification, the documentation.

== What is reused from the prototype

Taken: `pkg/glx` (with the changes above), the visual ID in `NewWindowAt`,
the rebinding of the context on window recreation, `console/glxoverlay`.

Not taken: the GPU scene in `renderer-opengl.go` with its texture caches and
shaders — its picture is not the `cpu` one; the phase timings in
`CaptureWindow` — capture is off the path of M1 and M2.
